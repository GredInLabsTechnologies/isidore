## Purpose
The `tests/test_connectors_f5.py` module tests the `McpConnector` class's interaction with a stub F5 server, simulating the JSON-RPC protocol used by the official Gmail server. It verifies that the connector correctly handles tool allowlists, argument passing, and security boundaries. The stub server mimics real-world behaviors like read-only operations, write tool rejection, and authentication failures, ensuring the connector adheres to the security constraints outlined in ADR-0032.

## Architecture
The module uses a pytest fixture `server` to launch a stub server as a subprocess, communicating over stdin/stdout. The server responds to JSON-RPC methods like `initialize`, `tools/list`, and `tools/call`, with special handling for authentication failures and write tool rejection. The connector's configuration is generated by `_config()`, which specifies the server path and allowed tools. Tests validate that arguments reach the server, write tools are blocked, and authentication failures are properly reported.

## Key entry points
- `server`: A pytest fixture that sets up the stub server environment and writes the server script to a temporary file.
- `_config`: Generates a configuration dictionary for the `McpConnector`, specifying the server path and allowed tools.
- `test_an_allowlist_entry_can_carry_the_arguments_a_real_tool_needs`: Validates that allowlist entries can include tool arguments.
- `test_the_arguments_actually_reach_the_server`: Ensures tool arguments are correctly passed to the server.
- `test_a_write_tool_is_refused_even_when_the_recipe_asks_for_it`: Confirms write tools are rejected even if requested.
- `test_a_revoked_token_fails_closed_and_writes_nothing`: Tests that authentication failures are handled securely.

## Dependencies
The module depends on `pytest`, `json`, `sys`, and `pathlib` for testing infrastructure and file operations. It imports `McpConnector`, `IngestOptions`, and `iter_items` from the `isidore.connectors` package to interact with the connector and validate results.

## How to change safely
When modifying this module, ensure:
1. The stub server's JSON-RPC methods remain compatible with the `McpConnector`'s expected behavior.
2. Authentication failure handling is preserved to maintain security boundaries.
3. Write tool rejection logic is not altered, as it enforces ADR-0032 constraints.
4. The `_config` function's structure is maintained to support the connector's initialization.
